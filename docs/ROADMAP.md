# Roadmap

Что запланировано после текущей задачи, в порядке, который кажется
правильным сейчас. Каждая строка — отдельная спека в
`docs/superpowers/specs/` перед началом работы.

## Приложение

1. **Каркас и ввод** — в работе. Спека `2026-09-19-app-entry-design.md`.
2. **Детализация по месяцам.** Список транзакций за месяц с источником,
   валютой, категорией, суммой в базовой валюте. Переключение месяцев.
   Фильтры по источнику и категории. Здесь же правка и удаление ручных
   записей и `code_override` для карточных.
3. **Статистика.** По месяцам и категориям, графики. Сравнение месяцев.
   Доля комиссий. Именно этот экран окончательно заменяет вкладку
   «Мониторинг».
4. **Настройки.** Базовая валюта, переключатель темы, список источников,
   редактирование категорий и правил по мерчантам (`merchant_rule` из
   интерфейса вместо SQL).
5. **Офлайн-режим.** Очередь записей в IndexedDB, отправка при появлении
   сети, индикатор «не отправлено». Очень желателен: ввод должен работать в
   магазине без связи. Нужен до того, как приложение станет основным
   способом ввода.
6. **Распознавание чеков.** Фото → Storage → Edge Function → vision-модель →
   черновик в отдельной таблице, подтверждение в интерфейсе, только потом в
   `raw_txn`. Делать после офлайна: ручной ввод занимает секунды, выигрыш
   есть только при большом числе чеков.

## Данные и конвейер

- **Холд и списание.** Проверить на реальном переходе `freeze → deduct`,
  задваивает ли Bybit запись. Если да — правило в `v_txn`, гасящее холд при
  наличии списания.
- **Возвраты.** Как выглядит возврат от мерчанта: отдельная запись со
  статусом 3 или перезапись исходной. Пока неизвестно.
- **Рыночные курсы.** Фид ЕЦБ в `fx_rate` с `source = 'ecb'`, приоритет
  уже заложен в `fx_to_base`.
- **Второй провайдер.** Отложен сознательно. Что придётся решить: нет
  стабильного id транзакции, файловый импорт вместо `fetchInPage`,
  отсутствие MCC. Описано в CLAUDE.md, раздел «Adding a provider».
- **Таблица.** Остаётся витриной до пункта 3 приложения, потом Apps Script
  можно выключить.

## Инфраструктура

- **Уход от Supabase** возможен, если приложение захочется распространять.
  Схема и вьюхи переносимы на любой Postgres; привязаны к Supabase только
  Auth, Edge Function и PostgREST-вызовы. Функции в `public` с
  `security definer` — граница, которую при переезде придётся заменить
  своим API.
- **Второй пользователь.** Потребует `user_id` в `raw_txn` и RLS либо
  проверки в функциях. Сейчас намеренно не заложено.
