# Приложение, задача 4: офлайн-режим

Дата: 2026-09-20. Статус: согласовано, ждёт план реализации.
Предыдущие задачи: `2026-09-19-app-entry-design.md`,
`2026-09-20-app-month-design.md`, `2026-09-20-app-stats-design.md` (в `main`).

## Цель

Ввод траты работает без связи: в магазине, в метро, при пустом мобильном
интернете. Запись ложится в очередь на устройстве и уходит в базу сама,
когда сеть вернётся. Экраны месяца и статистики без сети показывают
последние загруженные данные вместо ошибки.

## Решения

| вопрос | решение |
|---|---|
| Что работает без сети | добавление траты + просмотр последнего загруженного (вариант B) |
| Как видна неотправленная запись | как обычная строка со значком часов, плюс счётчик в шапке, только когда очередь не пуста (вариант C) |
| Отвергнутая базой запись | попытки останавливаются, запись помечена, счётчик красный, список с текстом ошибки и удалением (вариант A) |
| Хранилище | IndexedDB, тонкий слой без библиотек |
| Идентификатор записи | генерируется в приложении, повтор идемпотентен |
| Когда отправляем | появление сети, возврат в приложение, старт, тап по счётчику; без периодического опроса |
| Статистика | неотправленные не учитывает (считается сервером) |

## База: миграция `db/016_app_add_txn_id.sql`

`app_add_txn` получает шестой необязательный параметр `p_id text default null`.

**Важно:** в Postgres добавление параметра со значением по умолчанию создаёт
вторую функцию, а не заменяет первую, и вызов по именам параметров через
PostgREST становится неоднозначным. Поэтому миграция делает
`drop function public.app_add_txn(date, numeric, text, text, text)`, затем
`create` шестипараметровой версии, затем заново `revoke`/`grant`.

Тело меняется в двух местах:

```sql
  v_id text := coalesce(nullif(btrim(coalesce(p_id, '')), ''), gen_random_uuid()::text);
```

плюс проверка формата, если идентификатор пришёл снаружи:

```sql
  if p_id is not null and btrim(p_id) <> ''
     and btrim(p_id) !~ '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$' then
    raise exception 'Неверный идентификатор записи';
  end if;
```

и вставка получает `on conflict (source, external_id) do nothing`, а функция
всё равно возвращает `v_id`. Это и есть идемпотентность повторной отправки:
запрос дошёл, ответ потерялся, повтор ничего не задвоил.

Порядок проверок: сначала формат идентификатора, затем сумма, валюта, дата,
код — как сейчас. Отказ по любой проверке откатывает вставку, поэтому
исправленная запись с тем же идентификатором вставится нормально.

Остальные функции и `004_verify.sql` не трогаются.

### Хранилище

`db.ts` открывает одну базу `spend-offline` версии 1 с двумя объектными
хранилищами: `queue` (ключ `id`) и `cache` (ключ `key`). Экспортирует
`queueStorage: QueueStorage` и `cacheStorage: CacheStorage` — два узких
интерфейса:

```ts
interface QueueStorage {
  all(): Promise<QueuedTxn[]>;
  put(item: QueuedTxn): Promise<void>;
  remove(id: string): Promise<void>;
}
interface CacheStorage {
  get(key: string): Promise<{ value: unknown; at: string } | null>;
  set(key: string, value: unknown): Promise<void>;
}
```

`queue.ts` и `cache.ts` принимают эти интерфейсы, поэтому тестируются на
`memoryStorage`. Сам адаптер IndexedDB тестами не покрыт: в jsdom его нет, а
`fake-indexeddb` в зависимости не тянем. Все обращения к IndexedDB обёрнуты в
try/catch: если хранилище недоступно (приватный режим, запрет на данные
сайта), приложение работает как раньше, просто без очереди и кэша.

### Очередь

```ts
interface QueuedTxn {
  id: string;            // uuid, он же external_id
  args: AddTxnArgs;      // date, amount, currency, code, note
  createdAt: string;     // ISO
  attempts: number;
  error: string | null;  // текст отказа базы; null пока не отвергнута
}
```

- `enqueue(args)` создаёт `id` через `crypto.randomUUID()`, кладёт запись,
  обновляет слайс и сразу запускает `flush`.
- `flush()` однопоточная (модульный флаг). Берёт записи без `error` по
  возрастанию `createdAt` и отправляет по одной вызовом
  `app_add_txn` с `p_id`. Успех — `remove(id)`. Сетевая ошибка
  (`«Нет связи с сервером»`) — `attempts + 1`, обработка прерывается целиком.
  Любая другая ошибка — `error = текст`, `attempts + 1`, переходим к
  следующей. По завершении обновляет слайс и, если что-то ушло,
  инвалидирует тег `Txns`.
- `retry(id)` снимает `error` и запускает `flush`; `remove(id)` удаляет
  запись насовсем.

### Кэш чтения

`withCache(baseQuery, storage)` оборачивает существующий `rpcBaseQuery`:

- кэшируются только `app_codes`, `app_month_txns`, `app_monthly_stats`;
  ключ — `fn + JSON.stringify(args)`;
- успешный ответ пишется в `cache`, в слайс уходит `lastSyncAt = now`;
- ошибка «Нет связи с сервером» — читаем кэш; если он есть, возвращаем
  `{ data }` и пишем в слайс `fromCacheAt = запись.at`; если нет, отдаём
  ошибку как сейчас;
- мутации не кэшируются и из кэша не отвечают никогда.

`fromCacheAt` в слайсе один на всё приложение: он ставится при любом ответе
из кэша и сбрасывается при любом свежем успешном ответе, то есть отражает
последнее чтение. Отдельного флага на каждый запрос не делаем: сеть либо
есть, либо нет, и состояние сходится за один цикл запросов.

Экраны месяца и статистики показывают под заголовком строку «Данные от
20 сентября, 15:40» когда `fromCacheAt` не пуст.

`crypto.randomUUID()` доступен только в защищённом контексте: это localhost и
https, оба рабочих случая покрыты.

### Экраны

- **Ввод.** `onSubmit` вместо `addTxn(...)` вызывает `enqueue(...)` и всегда
  возвращает `true`; тост «Записано» как раньше. Список «Сегодня»
  подмешивает неотправленные записи за сегодня.
- **Месяц.** Список и итоги подмешивают неотправленные записи выбранного
  месяца. `base_amount` у подмешанной строки равен сумме, если её валюта
  совпадает с базовой, иначе `null` (такая строка не попадёт в итог, как и
  любая трата без курса).
- **Строка.** `TxnRow` рисует значок часов (символ `🕒` или текстовая метка
  «не отправлено») у строк с `pending`.
- **Полоска.** `OfflineBar` рендерится рядом с `TabBar` на всех экранах,
  только когда очередь не пуста: «Не отправлено: N», тап запускает `flush`.
  Если есть записи с `error`, полоска красная, тап открывает `PendingSheet`
  со списком: дата, сумма, категория, текст ошибки, кнопки «Отправить
  снова» и «Удалить».

### Определение сети

`useOffline()` в `main.tsx`: читает `navigator.onLine`, подписывается на
`online`/`offline` и на `visibilitychange`, при старте загружает очередь из
IndexedDB в слайс и запускает `flush`. Событие `online` и возврат видимости
тоже запускают `flush`.

## Проверка

- `queue.test.ts` на `memoryStorage`: добавление; успешная отправка убирает
  запись; сетевая ошибка сохраняет и прерывает обработку; отказ базы
  помечает свою запись и не мешает следующей; `retry` после правки; два
  одновременных `flush` не дублируют отправку.
- `cache.test.ts`: успешный ответ пишется; при сетевой ошибке читается;
  мутация не кэшируется и из кэша не отвечает; отсутствие кэша отдаёт
  исходную ошибку.
- `offlineSlice.test.ts`, `toDisplayRow.test.ts`.
- `OfflineBar.test.tsx`: скрыта при пустой очереди; показывает счётчик;
  краснеет при `error`; тап открывает список с текстом ошибки и удалением.
- `EntryScreen.test.tsx`: новый случай «нет сети» — `rpc` отвечает сетевой
  ошибкой, тост «Записано», строка со значком в «Сегодня», полоска
  «Не отправлено: 1». Существующие случаи остаются зелёными.
- База: `016` применена; под `set role authenticated` два вызова с одним
  `p_id` дают одну строку; вызов без `p_id` работает как раньше; мусор
  вместо uuid даёт «Неверный идентификатор записи»; `anon` не имеет доступа;
  `004_verify.sql` зелёная.
- Браузер: режим офлайн в DevTools — приложение открывается, категории на
  месте, запись сохраняется и видна со значком, полоска считает, экран
  месяца показывает кэш с отметкой времени; возврат сети отправляет очередь
  сама. Прямая ссылка `/month` открывается офлайн; если service worker так
  не умеет, добавить запасной переход на `index.html`.
