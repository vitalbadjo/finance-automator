# Импорт истории из Google Таблиц

Дата: 2026-09-21. Статус: согласовано, ждёт план реализации.

## Цель

Перенести в базу траты за июль 2018 – август 2026 из таблиц LFS-2018 …
LFS-2026 (лист «Мониторинг»), чтобы экраны месяца и статистики показывали
историю, а таблицы можно было закрыть. Курсы для рублёвых лет берутся у
ЦБ РФ. Импорт повторяем: второй запуск обновляет, а не задваивает.

## Что выяснилось при разборе (2026-09-21)

- Девять таблиц одной раскладки. Лист «Мониторинг»: двенадцать блоков по
  семь колонок (`дата · код · сумма · валюта · курс · итог · пусто`),
  строка на покупку, около 9 650 строк всего. Вкладка «Деньги» — формулы по
  мониторингу, её суммы сходятся с мониторингом.
- Базовая валюта таблиц — рубль: `курс` приводит сумму строки к рублю
  (`итог = сумма × курс`), для рублёвых строк курс = 1. Приложению нужен
  доллар, поэтому нужен курс RUB→USD на дату — его в таблице нет.
- Даты условные: 7 863 верных, 1 092 с чужим годом (скопированный блок),
  703 с чужим месяцем.
- Валюты: почти всё `RUR`; исключения — июль 2021 (`LYR` ×8 = турецкая
  лира, `EUR`, `USD`), март–май 2022 (`USD` ×31), март 2023 (`BTH` ×48 =
  тайский бат), август 2026 (`USD` ×1).
- 41 код вне справочника: настоящие категории, переводы/накопления и
  опечатки. Решения ниже.
- В LFS-2026 сентябрь и дальше пишет скрипт из базы — не импортируются.

## Решения

| вопрос | решение |
|---|---|
| Как читать таблицы | через коннектор Google Drive выгружаются xlsx, лежат локально (в git не попадают) |
| Гранулярность | строка на покупку, как в мониторинге |
| Курсы | ЦБ РФ, дневные, `source = 'cbr'`, для USD/EUR/TRY/THB (вариант A) |
| Инструмент | `tools/sheets/` на Python без зависимостей + одна миграция (вариант A) |
| Неизвестные коды | завести настоящие категории (скрытые), опечатки сопоставить, переводы и накопления импортировать как переводы (вариант A) |
| Даты | месяц из блока, год из файла, день из ячейки только если совпадает с блоком, иначе 1-е |
| Идемпотентность | `external_id = sheet-YYYY-MM-NNN`, NNN — номер строки в блоке, upsert по `(source, external_id)` |

## База: миграция `db/018_sheet_import.sql`

- `insert into spend.source (code, title) values ('sheet', 'Таблица LFS')
  on conflict do nothing`.
- Новые коды в `code_ref` из таблицы выше, `on conflict (code) do nothing`
  (уже существующие не трогаются).
- `public.spend_import_sheet_rows(p_rows jsonb) returns int` —
  `security definer`, права как у `spend_ingest` (только `service_role`;
  запускается через `supabase db query`, то есть от `postgres`). Каждый
  элемент `p_rows`:

```json
{ "external_id": "sheet-2025-03-017", "date": "2025-03-11",
  "amount": 1545, "currency": "RUB", "code": "каф", "transfer": false,
  "title": "Кафе, рестораны",
  "payload": { "via": "sheet", "year": 2025, "month": 3, "row": 17,
               "sheet_code": "каф", "sheet_currency": "RUR",
               "sheet_rate": 1, "total_rub": 1545 } }
```

  Вставка в `raw_txn`: `source = 'sheet'`, `txn_at = (date::timestamp at
  time zone 'Europe/Belgrade')`, `merchant_raw = merchant_name = title`,
  `amount`, `currency`, `txn_type = 'deduct'`, `display_status = '1'`,
  `message_type = case when transfer then '2' else '1' end`,
  `code_override = case when transfer then null else code end`, `payload`.
  `on conflict (source, external_id) do update` по всем этим полям.
  Проверки: `code` (если не перевод) существует в `code_ref`, `amount > 0`,
  `currency` — три латинские буквы; отказ откатывает всю пачку с текстом
  `Неизвестная категория: …` / `Неверная строка: …`.
- Ничего в `v_txn`, правилах и `004_verify.sql` не меняется. Курс к USD
  считается штатно через `fx_to_base` по `fx_rate`.

## Скрипты `tools/sheets/`

Python 3.11, только стандартная библиотека. Вызов базы — через
`subprocess` и `supabase db query --linked` (json-вывод), без ключей в коде.

### `xlsx.py`

Минимальный читатель xlsx (zipfile + xml): `load(path) -> {лист:
{(row, col): value}}`; общие строки, числа, даты как серийные числа.

### `import_sheets.py`

```
python3 tools/sheets/import_sheets.py --dry-run  ~/lfs/LFS-*.xlsx
python3 tools/sheets/import_sheets.py            ~/lfs/LFS-*.xlsx
```

- Год — из имени файла `LFS-YYYY.xlsx`. Для 2026 берутся блоки 1–8.
- Строка блока считается, если заполнены код и сумма. Нумерация `NNN` —
  порядковый номер такой строки внутри блока, с единицы.
- Дата: серийное число → дата; если её год и месяц совпадают с файлом и
  блоком — берётся как есть, иначе 1-е число месяца блока.
- Код: `btrim`, сопоставление опечаток, проверка по списку известных кодов
  (читается из базы: `select code, title from spend.code_ref`); перевод —
  по списку выше. Неизвестный код останавливает прогон с перечнем.
- Валюта: как в решениях. Курс и итог из таблицы — только в `payload`.
- Отчёт: по каждому году и месяцу число строк, сумма `total_rub`, валюты;
  внизу коды и их количество. В сухом прогоне ничего не пишется.
- Запись: пачками по 500 строк, `select public.spend_import_sheet_rows($$json$$::jsonb)`
  через `supabase db query --linked`; итог — число строк на пачку.
- После записи сверка: `select year, month, sum((payload->>'total_rub')::numeric)
  from raw_txn where source='sheet'` против сумм из файлов; расхождение
  печатается.

### `cbr_rates.py`

```
python3 tools/sheets/cbr_rates.py --from 2018-07-01 --to 2026-08-31
```

- Источник: `https://www.cbr.ru/scripts/XML_dynamic.asp?date_req1=DD/MM/YYYY&date_req2=DD/MM/YYYY&VAL_NM_RQ=<id>`,
  идентификаторы: USD `R01235`, EUR `R01239`, TRY `R01700J`, THB `R01675`.
  Ответ — `Record Date="DD.MM.YYYY"` с `Nominal` и `Value` (запятая как
  разделитель). Курс к рублю = `Value / Nominal`.
- `fx_rate.rate` — единиц валюты за один USD: для `RUB` это курс USD; для
  EUR/TRY/THB — `rub_per_usd / rub_per_cur` на ту же дату (если у валюты
  нет записи на дату USD, дата пропускается).
- Запись `insert … on conflict (rate_date, currency, source) do update`,
  `source = 'cbr'`, пачками по 500. Отчёт: число дат по валютам.
- Приоритет источников в `fx_to_base` не меняется: на одну дату сначала
  `ecb`, потом остальные; для старых лет других источников нет.

## Порядок выполнения

1. Миграция `018` применена.
2. `cbr_rates.py` за 2018-07-01 … 2026-08-31.
3. `import_sheets.py --dry-run` по девяти файлам, проверка отчёта.
4. `import_sheets.py` без флага; сверка сумм.
5. Проверки ниже.

## Проверка

- Сухой прогон: строк ≈ 9 650, неизвестных кодов нет, суммы по месяцам
  совпадают с вкладкой «Деньги» (например 2025-01 = 148 397 ₽).
- `select count(*) from spend.v_missing_rates` = 0 после загрузки курсов.
- `select count(*) from spend.raw_txn where source = 'sheet'` равно числу
  строк из отчёта; повторный запуск импорта не меняет счётчик.
- `select month, code, amount from public.app_monthly_stats('2025-01-01','2025-12-31')`
  даёт ненулевые суммы в USD по каждому месяцу.
- `db/004_verify.sql` зелёная.
- Браузер: статистика показывает историю за 12 месяцев; месяц 2025-03
  открывается, строки помечены «таблица»; переводы (`инв`) видны в
  «снятия/переводы», а не в расходах.
