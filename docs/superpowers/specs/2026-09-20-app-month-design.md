# Приложение, задача 2: детализация по месяцам

Дата: 2026-09-20. Статус: согласовано, ждёт план реализации.
Предыдущая задача: `2026-09-19-app-entry-design.md` (сделана, в `main`).

## Цель

Экран «Месяц»: итог расходов и суммы по категориям сверху, список
транзакций за месяц по дням снизу, переключение месяцев, правка и удаление
ручных записей, смена категории у любой транзакции. После этой задачи в SQL
Editor больше не нужно ходить за исправлениями.

## Решения

| вопрос | решение |
|---|---|
| Верх экрана | итог месяца и категории, список под ними (вариант A) |
| Правка карточных | только категория через `code_override` (вариант A); удаления нет |
| Снятия наличных | видны в списке со своей меткой, в итогах отдельной строкой «снято наличными», в сумму расходов не входят |
| Холды в обработке | показываются как расход с пометкой «в обработке», как в `v_daily` |
| Отказы, нулевые авторизации | скрыты; режим «все операции» — позже |
| Фильтр по категории | тап по чипу категории в итогах, повторный тап снимает |
| Фильтр по источнику | переключатели «карта» / «вручную», видны только если источников больше одного |
| Навигация | нижняя панель «Ввод» / «Месяц»; месяц в состоянии экрана и в `?m=YYYY-MM` |

## База: миграция `db/013_app_edit.sql`

Чтение остаётся на `app_month_txns`. Одно дополнение: в её `returns table`
добавляется колонка `code_override text` (в конец), чтобы приложение
отличало категорию, поставленную руками, от категории по правилу.
Изменение сигнатуры возврата требует `drop function` + `create`, права
выдаются заново.

Три новые функции в `public`, `security definer`,
`set search_path = spend, public`, `revoke all ... from public, anon`,
`grant execute ... to authenticated, service_role`.

### `app_update_txn(p_id text, p_date date, p_amount numeric, p_currency text, p_code text, p_note text default null)`

- Ищет строку `source = 'manual' and external_id = p_id`; если нет —
  `raise exception 'Запись не найдена'`. Если запись найдена в другом
  источнике — `raise exception 'Карточную операцию править нельзя'`.
- Проверки как в `app_add_txn`: сумма `> 0 and < 1e12`, валюта три
  латинские буквы, код есть в `code_ref`, дата не null.
- Обновляет `txn_at` (полночь Белграда), `amount`, `currency`,
  `code_override`, `merchant_raw` и `merchant_name`
  (`coalesce(note, title)`), `payload = payload || {"note": ...}`,
  `last_seen_at = now()`.
- Возвращает `external_id`.

### `app_delete_txn(p_id text)` → `int`

Удаляет `source = 'manual' and external_id = p_id`. Если строка есть в
другом источнике — та же ошибка «Карточную операцию править нельзя».
Возвращает число удалённых строк; приложение ожидает 1.

### `app_set_code(p_source text, p_id text, p_code text)` → `void`

Пишет `code_override = p_code` для любого источника. `p_code = null`
снимает переопределение. Непустой код должен существовать в `code_ref`,
иначе «Неизвестная категория». Если строка не найдена — «Запись не
найдена».

### Что не меняется

Вьюхи, `spend_ingest`, `004_verify.sql`.

### Данные

- `useGetMonthTxnsQuery(monthRange(month))` — одна выборка на месяц.
- В `api.ts` добавляются мутации `updateTxn`, `deleteTxn`, `setCode`
  (все инвалидируют `Txns`), тип `MonthTxn` получает
  `code_override: string | null`.
- `summarize(txns)` возвращает:
  `{ total: number; byCode: { code: string; amount: number }[];
     cashOut: number; missingRate: number }`, где `total` и `byCode` — только
  `kind === 'expense'` и `base_amount != null`, в базовой валюте, `byCode`
  по убыванию; `cashOut` — `kind === 'transfer' && status === 'success'`;
  `missingRate` — число строк `expense` с `base_amount == null`.
- `groupByDay(txns)` → `{ date: string; subtotal: number; rows: MonthTxn[] }[]`,
  дни по убыванию, строки внутри дня по `txn_at desc`; в `subtotal` только
  `expense` с `base_amount`.
- Показываемые строки: `kind in ('expense', 'transfer')`; `void` и `auth`
  отфильтровываются до `summarize`/`groupByDay`.

### Экран

- **Шапка**: `‹ Сентябрь 2026 ›`. Стрелка вправо неактивна, когда месяц
  текущий. Месяц хранится в `useSearchParams` как `m=YYYY-MM`; без
  параметра — текущий.
- **Итоги**: сумма крупно (`formatMoney(total, base_currency)`), строка
  чипов «код · сумма» по убыванию, горизонтальная прокрутка. Тап по чипу —
  фильтр по коду (`aria-pressed`), повторный тап снимает. Под чипами:
  «Снято наличными N», если `cashOut > 0`; «N трат без курса, не в итоге»,
  если `missingRate > 0`; переключатели источника «карта» / «вручную»
  (`aria-pressed`), только если в месяце оба источника.
- **Список**: секция на день, заголовок «19 сентября · 42,10 USD».
  Строка: код (или «?» если null), заметка или мерчант, метка источника,
  справа сумма в валюте операции и, если `currency !== base_currency`,
  под ней сумма в базовой мелким шрифтом. Снятие наличных: метка
  «наличные», сумма показана, в подытог не входит. Холд: метка
  «в обработке». Пустой месяц: «За этот месяц записей нет».
- **Правка ручной** (тап по строке `source === 'manual'`): `Sheet` с
  `EntryForm` (initial из строки, `submitLabel="Сохранить"`) и кнопкой
  «Удалить»; первый тап превращает её в «Точно удалить», второй вызывает
  `deleteTxn`. Успех любой операции закрывает шторку и показывает тост
  «Сохранено» / «Удалено»; ошибка — тост с текстом, шторка остаётся.
- **Правка карточной** (тап по строке другого источника): `Sheet` с
  `CodePicker` (текущий код выбран) и кнопкой «Сбросить на правило»,
  видимой только если `code_override != null`. Выбор кода → `setCode`,
  сброс → `setCode(null)`; успех закрывает шторку.
- **Нижняя панель** `TabBar`: «Ввод» (`/`), «Месяц» (`/month`), активный
  пункт выделен, `aria-current="page"`.

### Вынос формы

`EntryForm` содержит всё, что сейчас внутри `EntryScreen` между шапкой и
списком: сумма, валюты с «+», категории с шторкой, дата, заметка, кнопка.
Состояние формы (`useReducer`) переезжает внутрь `EntryForm`; `EntryScreen`
передаёт `onSubmit`, сбрасывает сумму и заметку через возвращаемое из формы
API (`ref`-метод `afterSave()` или повторный `initial`). Поведение экрана
ввода не меняется, его тесты остаются зелёными.

## Проверка

- `summary.test.ts`: итог только по `expense` с курсом; `cashOut` отдельно;
  `byCode` по убыванию; `missingRate`; `groupByDay` — порядок дней и строк,
  подытоги без снятий.
- `MonthScreen.test.tsx` (замоканный `rpc`): рендер итогов и списка;
  фильтр по чипу; правка ручной вызывает `app_update_txn` с
  `p_id, p_date, p_amount, p_currency, p_code, p_note`; удаление требует
  второго тапа и вызывает `app_delete_txn`; тап по карточной и выбор кода
  вызывает `app_set_code`; стрелка вправо неактивна в текущем месяце.
- `EntryScreen.test.tsx` остаётся зелёным.
- База: под `set role authenticated` — обновить и удалить тестовую ручную
  запись; `app_delete_txn` на карточной даёт «Карточную операцию править
  нельзя»; `app_set_code` ставит и снимает `code_override`;
  `004_verify.sql` зелёная.
